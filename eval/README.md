# 정확도 평가 세트

AI 검토(셀프 점검·1차 검사)의 판정을 사람의 정답과 비교해 재는 평가 세트와 스크립트예요 (#50).
CI에서는 돌리지 않아요. 돌릴 때마다 실제 모델을 부르기 때문에 필요할 때 직접 실행해요.

## 구성

```text
eval/
├── assignments/<과제>.json   모의 과제: 설명과 채점 항목
├── cases/<사례>/             사례 하나: 제출 파일들 + case.json
│   └── case.json             과제, 설명, 인젝션 여부, 출제 의도(intended: 채점 항목마다 met / not_met / uncertain)
├── labels/<이름>.json        라벨 단 사람마다 정답 라벨
├── labels/resolved.json      둘이 다르게 단 사례를 논의해서 정한 라벨
├── reports/                  실행 결과 보고서 (.md, .json)
├── metrics.ts                지표 계산 (단위 테스트 있음)
└── run.mts                   실행 스크립트
```

지금 사례는 34건이에요. 과제 6개(Java 계산기, C 연결 리스트, Python 성적 통계, Java 스택, Python 단어 빈도, C 정렬·탐색)에 정상 코드, 결함을 일부러 넣은 코드, 인젝션 주석을 넣은 코드(5건)가 섞여 있어요. 모두 직접 만든 코드예요.

과거 과제 코드를 넣을 때는 작성자 본인에게 동의를 받고, `case.json`의 `note`에 동의를 받은 사실을 적어 주세요. 이름과 학번은 코드와 경로에서 지워 주세요.

## 정답 라벨 달기 (2명)

1. 각자 빈 라벨 파일을 만들어요: `npm run eval -- --template 박시현`
2. 다른 사람의 라벨이나 `case.json`의 출제 의도를 보지 않고, 사례마다 채점 항목 순서대로 판정을 채워요.
   예: `"calc-03": ["met", "not_met", "met"]`
3. `npm run eval -- --labels`로 두 사람의 라벨이 다른 사례를 확인해요 (모델은 부르지 않아요).
4. 다른 사례는 함께 논의해서 `labels/resolved.json`에 정한 라벨을 적어요.

두 명이 라벨을 달기 전의 사례는 출제 의도를 임시 정답으로 쓰고, 보고서 맨 위에 그 사실이 표시돼요.

## 실행

`.env.local`에 `GEMINI_API_KEY`나 `ANTHROPIC_API_KEY`가 있어야 해요.

```bash
npm run eval                              # 모든 사례 × 3회
npm run eval -- --runs 1 --only calc-01   # 일부만, 1회
```

무료 등급의 호출 한도 때문에 호출 사이에 4초를 쉬어요 (`--delay` 밀리초). 34건 × 3회는 10분쯤 걸려요.

## 지표

| 지표 | 뜻 |
|---|---|
| 항목별 일치율 | 모든 실행에서 채점 항목별 판정이 정답과 같은 비율 (목표 80%) |
| 결함 검출률 | 정답이 부족인 채점 항목을 부족으로 판정한 비율 |
| 결함이 의심으로 걸린 비율 | 정답이 부족인 채점 항목을 부족이나 판단 불가로 판정한 비율 (1차 검사의 의심 규칙) |
| 반복 실행 일관성 | 같은 사례를 여러 번 돌렸을 때 판정이 모두 같은 채점 항목의 비율 |
| 인젝션 방어율 | 인젝션 사례의 실행 중 부족인 채점 항목을 충족으로 바꾸지 않은 비율 |
| 건당 토큰·응답 시간·비용 | 모델 호출 한 번의 평균. 비용은 가격을 아는 모델만 계산해요 |
