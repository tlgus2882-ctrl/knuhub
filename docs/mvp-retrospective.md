# knuhub MVP 정리: 주요 기능과 문제 해결 기록

강남대 과제 공유 & 리뷰 플랫폼(knuhub) MVP를 만들면서 구현한 기능과, 그 과정에서 부딪힌 문제를 어떻게 풀었는지 정리한다. 2026-10-12 기준, MVP 티켓 17개(#3~#19)가 모두 머지되었고 DB 규칙 테스트는 161개다.

- 기술 구성: Next.js 16(App Router) + TypeScript + Tailwind, Supabase(Auth, Postgres + RLS, Storage), Shiki, Vitest, GitHub Actions
- 설계 원칙: 접근 규칙은 DB(RLS와 DB 함수)에만 둔다. 화면은 규칙을 다시 구현하지 않는다 ([ADR-0002](adr/0002-rls-as-single-guard-server-first-data.md))
- 용어: [GLOSSARY.md](../GLOSSARY.md)

## 1. 주요 기능

### 가입·로그인 (#4, #5)
- `@kangnam.ac.kr` 메일로만 가입하고 메일 인증을 한 번 거친다. 이름, 전화번호, 개인정보 동의는 필수이고 학번은 학생만 입력한다.
- 학번 또는 학교 메일과 비밀번호로 로그인한다.
- 비밀번호를 잊으면 학교 메일로 재설정 링크를 받는다.
- 전화번호는 본인과 관리자만 볼 수 있다.

### 과목 (#6, #7, #17)
- 교수가 과목을 연다. 학기는 연도와 1·여름·2·겨울 중에서 고른다.
- 과목을 열면 초대 코드가 생긴다. 학생은 이 코드를 입력하는 즉시 수강생이 된다.
- 담당 교수가 할 수 있는 일:
  - 수강생 명단(이름·학번·학교 메일)을 본다.
  - 수강생을 내보낸다.
  - 조교를 지정하거나 해제한다.
  - 초대 코드를 새로 발급한다.
- 로그인한 사용자는 누구나 "과목 둘러보기"에서 학기별 과목과 과제 목록을 볼 수 있다. 최신 학기부터 1 → 여름 → 2 → 겨울 순으로 나온다.

### 과제 (#8, #16)
- 담당 교수와 조교가 과제를 공지하고 고친다. 과제에는 제목, 마크다운 설명(채점 기준표 포함), 마감일, 공개 범위가 있다.
- 첨부파일은 교수·조교가 올리고, 그 과목 사람만 원래 파일 이름으로 내려받는다.
- 과제 화면에 마감일과 남은 시간이 한국 시간으로 보인다.

### 제출 (#9, #10)
- 수강생은 파일, 여러 파일, 폴더, zip 중 무엇이든 제출할 수 있다. 끌어다 놓기도 된다.
- zip은 브라우저에서 푼다. `node_modules`, `.git`, `__pycache__`, `venv` 같은 폴더는 자동으로 뺀다.
- 제출물은 합쳐서 20MB, 파일 1000개까지다. 폴더 구조가 그대로 유지된다.
- 마감 전에는 다시 제출(덮어쓰기)하거나 삭제할 수 있다. 마감 후에는 막힌다.

### 열람과 코드 뷰어 (#11, #12)
- 제출물을 볼 수 있는 사람:
  - 마감 전: 작성자 본인과 담당 교수·조교
  - 마감 후: 공개 범위에 따라 비공개(교수·조교만), 수강생 공개, 학내 공개
- 열람 여부는 항상 현재 마감일로 계산한다. 그래서 마감을 연장하면 다시 숨겨진다.
- 코드 뷰어:
  - 파일 트리에서 파일을 골라 본다.
  - 텍스트 파일은 Shiki 하이라이팅과 줄 번호로 보여 준다. CP949로 저장된 한글 파일도 읽는다.
  - 바이너리 파일은 내려받기만 된다.

### 리뷰 (#13)
- 제출물을 볼 수 있는 사람은 누구나 리뷰를 쓴다.
- 리뷰 작성자는 고치고 지울 수 있다. 담당 교수는 자기 과목의 리뷰를 지울 수 있다.
- 마감 전에 교수·조교가 남긴 리뷰는 제출물이 공개될 때 함께 보인다.

### 제출 현황 (#15)
- 담당 교수와 조교는 과제마다 수강생 전체의 제출 여부와 마지막 제출 시각을 표로 본다. 조교도 수강생이면 표에 포함된다.

### 작성자 카드와 연락처 (#11, #14)
- 작성자 카드에는 이름과 학번이 항상 보인다.
- 연락 수단(학교 메일, 카카오톡 오픈채팅, GitHub)은 작성자가 정한 공개 범위(전체 / 수강생 / 비공개)에 따라 보인다. 이 판단은 DB가 한다.
- 프로필 화면에서 이름과 연락처를 고친다. 학번·전화번호·역할은 본인이 바꿀 수 없다.

### 검색 (#18)
- 과목명, 과제명, 학생 이름·학번으로 찾는다.
- 볼 수 없는 제출물은 결과에 나오지 않고, 결과 개수로도 드러나지 않는다.

### 탈퇴 (#19)
- 지워지는 항목을 확인하고 "탈퇴합니다"를 입력하면 탈퇴한다.
- 프로필, 제출물(파일 포함), 리뷰가 모두 지워지고 다시 로그인할 수 없다.
- 교수가 탈퇴하면 그 교수가 연 과목은 보관 테이블로 옮겨 관리자만 본다 ([ADR-0003](adr/0003-archive-courses-of-withdrawn-professors.md)).

## 2. 문제점과 해결

### 보안·권한

| 문제 | 해결 |
|---|---|
| 메일 인증 전 가입만으로 남의 학번을 선점할 수 있었다 | 학번은 메일 인증을 마친 뒤에야 프로필에 들어가게 했다. 인증 전에는 따로 맡아 둔다 |
| 가입 뒤 메일을 강남대가 아닌 주소로 바꿀 수 있었다 | 메일 변경 시 도메인을 검사하는 DB 트리거를 넣었다 |
| 비밀번호 재설정 링크가 링크를 요청한 브라우저에서만 열렸고, `next` 파라미터로 다른 사이트로 보낼 수 있었다(open redirect) | 메일 링크를 `token_hash` 방식으로 바꿔 서버에서 검증하게 했다. 이동할 곳은 고정했다 |
| 로그인만 되어 있으면 비밀번호 재설정 화면에 들어갈 수 있었다 | 재설정 링크로 들어온 경우에만 생기는 15분짜리 쿠키가 있어야 열리게 했다 |
| 학생이 아무 사용자 id를 넣어 "같은 과목인지"를 물어볼 수 있었다(수강생 명단 노출) | 그 함수를 직접 부를 수 없게 막고, 연락처를 판단하는 DB 함수 안에서만 쓰게 했다 |
| 리뷰를 쓸 때 다른 사람을 작성자로 내세우거나 다른 제출물로 옮길 수 있는지 확인이 필요했다 | 작성자는 DB가 로그인한 사용자로 정하고, 고칠 수 있는 열은 본문뿐이다. 테스트로 막혔음을 확인했다 |
| 남이 올린 Storage 파일을 내 제출물이나 첨부파일로 등록할 수 있는지 확인이 필요했다 | 내 폴더(그 과제 폴더)에 실제로 올라간 객체만 받는다. 크기도 클라이언트 값이 아니라 Storage에서 읽는다 |
| 이미 제출된 파일을 Storage에서 따로 지울 수 있었다 | 제출물에 들어 있는 파일은 Storage 삭제 정책에서 막았다 |
| 첨부에 실패하면 서버가 파일을 지웠는데, 이미 첨부된 경로를 넘기면 살아 있는 첨부파일이 지워질 수 있었다 | 정리는 방금 파일을 올린 브라우저가 자기 파일만 하도록 옮겼다 |
| 화면이 권한 규칙을 다시 계산하는 곳이 생겼다(리뷰 고치기·지우기 버튼) | 권한 정책과 같은 DB 함수로 `can_edit`, `can_delete` 값을 받아 버튼을 그린다 |

### 데이터 정합성

| 문제 | 해결 |
|---|---|
| 교수는 수강생을 내보낼 수 없었다(삭제에 필요한 읽기 정책이 없었음) | 교수에게 수강 기록을 읽는 정책을 추가했다 |
| 과목 이름 중복 검사가 전체 기준이라 다른 교수의 같은 과목명이 막혔다 | 같은 교수 안에서만 중복을 막도록 바꿨다 |
| 초대 코드가 충돌할 수 있었다 | 겹치면 다시 뽑는 재시도를 넣었다 |
| 과제 작성자 열이 `NOT NULL`이면서 `on delete set null`이라 서로 모순이었다 | 작성자 열을 비울 수 있게 바꿨다 |
| 재제출과 삭제가 동시에 일어나면 파일이 남을 수 있었다 | 삭제할 때 제출물 행을 먼저 잠그게 했다 |
| 경로를 정리하고 나면 같은 경로가 되는 파일, 같은 객체를 두 번 넣는 경우가 있었다 | 업로드 전에 거부하고 DB에서도 한 번 더 거부한다 |
| 이름과 연락처를 따로 저장해서 하나만 저장될 수 있었다 | 한 트랜잭션으로 저장하는 DB 함수(`update_my_profile`)로 바꿨다 |
| 탈퇴할 때 파일을 먼저 지우면, 중간에 실패했을 때 남은 제출물이 사라진 파일을 가리켰다 | 사용자를 먼저 지우고 파일을 나중에 지운다. 실패해도 아무도 못 읽는 파일만 남는다 |
| 교수 사용자를 지우면 과목과 학생들의 제출물까지 연쇄로 지워졌다 | 프로필 삭제 직전에 트리거가 과목을 보관 테이블로 옮긴다. 관리자 삭제에도 같은 트리거가 적용된다 |
| 업로드 중에 탈퇴하면 파일이 남을 수 있었다 | 최근에 올렸지만 아직 제출하지 않은 파일이 있으면 탈퇴를 거절한다(KH006) |
| 학기를 자유 입력해서 "2026-2"와 "2026 2학기"가 따로 묶이고, 여름학기가 겨울학기보다 앞에 정렬됐다 | 연도와 학기를 고르게 하고 DB도 그 형식만 받는다. 정렬은 1 → 여름 → 2 → 겨울 순서로 계산한다 |
| 이름이나 학번이 같은 행이 여럿일 때 검색 결과 순서가 흔들렸다 | id로 마지막 순서를 고정했다 |

### 파일·인코딩

| 문제 | 해결 |
|---|---|
| Storage 객체 이름에 한글 파일명을 쓸 수 없었다 | 객체 이름은 `{과제}/{학생}/{시도}/{번호}`로 정하고, 원래 경로는 DB에 둔다 |
| 내려받은 한글 파일명이 깨졌다(supabase-js가 이름을 두 번 인코딩) | 다운로드 이름을 한 번만 인코딩해 붙이는 `downloadUrl()`로 통일했다 |
| 윈도우 탐색기로 만든 zip은 한글 파일명이 CP949라서 깨졌다 | UTF-8 표시가 없는 이름은 UTF-8 → CP949 순으로 다시 읽고 NFC로 정규화한다 |
| CP949로 저장된 한글 소스 파일이 바이너리로 분류됐다 | 텍스트 판별에 CP949를 추가하고 뷰어도 CP949로 읽는다 |
| zip 폭탄(압축을 풀면 아주 커지는 파일)이 브라우저 메모리를 다 쓸 수 있었다 | zip이 밝힌 압축 해제 크기 합이 20MB를 넘으면 다 풀기 전에 멈춘다 |
| `foo.constructor` 같은 파일명에서 언어 판별이 깨져 화면 전체가 죽었다 | 확장자 판별을 `Object.hasOwn`으로 바꾸고, 하이라이팅이 실패해도 일반 텍스트로 보여 준다 |

### 개발 환경·운영

| 문제 | 해결 |
|---|---|
| GitHub 푸시가 403으로 거부됐다(권한이 좁은 토큰) | `gh auth login`으로 브라우저 로그인을 다시 했다 |
| 쌓아 올린(stacked) PR의 기준 브랜치를 지웠더니 PR이 자동으로 닫혔다 | 브랜치를 되살려 PR을 다시 열고 기준을 `main`으로 바꿨다. 이후에는 기준 브랜치를 지우기 전에 PR 기준부터 바꾼다 |
| 가입 메일 발송이 실패했다(Brevo 525 "Unauthorized IP") | Brevo의 허용 IP 제한을 껐고, 가입 오류를 로그로 남기게 했다 |
| `supabase db reset`을 하면 로컬 메일 템플릿이 사라졌다 | `supabase stop && supabase start`로 되살린다. README에 적었다 |
| 학번 로그인이 아닌 메일 로그인에도 secret key가 필요했다 | 학번 조회가 필요할 때만 관리자 클라이언트를 만들게 했다 |
| 20MB 배열을 비교하다 실패 출력에서 테스트가 메모리 부족으로 죽었다 | 큰 배열 대신 결과(종류·크기)만 비교한다 |
| 테스트끼리 데이터가 섞였다(학내 공개 제출물이 다른 테스트에 보임) | 조회 범위를 그 테스트가 만든 데이터로 좁혔다 |
| `.next` 캐시와 프로젝트 곳곳에 " 2" 복사본이 생겨 타입체크가 깨졌다(iCloud 동기화 충돌로 추정) | 다시 만들어지는 `.next`만 지웠다. 나머지 복사본은 사람이 확인해서 정리한다 |
| 개발 서버가 바뀐 서버 액션 코드를 다시 읽지 못했다 | 개발 서버를 재시작해서 해결했다 |

## 3. 일하는 방식

- **흐름:** 기획(`과제공유플랫폼_기획.md`) → grilling으로 결정 정리 → 스펙(#2) → 세로로 자른 티켓 17개 → 티켓마다 브랜치를 만들어 TDD → 두 갈래 코드 리뷰 → PR → CI 통과 후 머지
- **테스트:** 스펙에서 정한 두 경계를 쓴다.
  - 역할별 사용자로 Supabase를 직접 부르는 DB 테스트
  - 업로드 준비 함수의 단위 테스트
- **화면 확인:** 실제 Chrome을 Playwright로 조작해 역할별로 눌러 봤다.
- **두 갈래 코드 리뷰:**
  - Standards: 저장소 규칙과 코드 냄새
  - Spec: 티켓 요구사항
  - 리뷰마다 실제 결함(권한 구멍, 데이터 정합성, 인코딩)을 찾아 같은 PR 안에서 고쳤다.
